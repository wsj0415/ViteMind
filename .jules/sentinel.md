## 2025-01-20 - SSRF Protection Implementation
**Vulnerability:** The news generation script (`scripts/generate_news.py`) fetched URLs from RSS feeds and external services without validating that the target IP address was public. This exposed the server to Server-Side Request Forgery (SSRF) attacks, potentially allowing access to internal network resources (localhost, private IPs).
**Learning:** Even in scripts that seem to only fetch "trusted" public feeds, defense-in-depth is crucial. If the feed list is compromised (e.g., via database injection), the script becomes a proxy for attacking the internal network. relying solely on the "intent" of the script is insufficient; technical controls must enforce boundaries.
**Prevention:** Implemented a `validate_url` function using `socket.gethostbyname` and `ipaddress` to check if a resolved IP is private, loopback, or link-local before performing any HTTP requests. This pattern should be applied to all server-side HTTP clients.
